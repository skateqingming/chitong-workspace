# 国内上线逐步照做版

目标：把“赤瞳工作空间”上线成一个中国国内员工可以稳定访问的网址，先能用，再逐步变成正式企业系统。

这份方案同时考虑三件事：

- 公司官网：外部客户能访问。
- 内部管理系统：员工和管理员登录使用。
- 未来 App：iPhone/Android 或小程序继续调用同一个后端。

## 我建议的国内方案

### 方案 A: 最稳的正式方案

- `腾讯云轻量应用服务器`
- `腾讯云 PostgreSQL`
- 备案后的国内域名
- `HTTPS`

腾讯云轻量应用服务器支持中国内地地域，适合轻量 Web 应用和团队内部系统；腾讯云 PostgreSQL 负责数据库托管和高可用运维。

适合：

- 公司正式内部使用
- 员工经常在中国大陆访问
- 希望后续继续接企业微信、钉钉或飞书登录

### 方案 B: 先快跑再升级

- 先用腾讯云轻量应用服务器
- 先把当前项目跑成一个可访问的网址
- 数据暂时先放在服务器本地 JSON 文件或 SQLite
- 等流程跑顺后，再切到 PostgreSQL

适合：

- 你想先把网址发给同事试用
- 不想一次把数据库、登录、权限全部做完

## 推荐顺序

先做方案 B，后切方案 A。

原因很简单：

- 先让公司的人真能打开
- 再把数据、权限、审计慢慢做实
- 不会一开始就卡在备案、数据库迁移、权限接入上

## 最有性价比的购买选择

### 我建议你现在买

```text
腾讯云轻量应用服务器
Ubuntu 22.04 LTS
2 核 4G
中国大陆地域
```

这个配置适合：

- 跑公司官网
- 跑内部管理系统
- 跑 Nginx 和 Docker
- 给未来 App 后端留一点余量

### 极限省钱选项

```text
腾讯云轻量应用服务器
Ubuntu 22.04 LTS
2 核 2G
中国大陆地域
```

这个能省钱，但我只建议短期试用。公司官网、内部系统和未来 App 都放上去以后，`2 核 2G` 会比较紧。

### 暂时不要买

- 云数据库 PostgreSQL
- 对象存储 COS
- CDN
- 负载均衡
- 高防

这些不是不要，而是第二阶段再买。现在先把系统跑起来，确认公司真的开始用，再把钱花在正确的位置。

## 第 1 步：准备账号和域名

1. 注册腾讯云账号。
2. 完成实名认证。
3. 买一个公司域名，建议用 `.com` 或 `.cn`。
4. 如果你选的是中国大陆服务器，继续做备案。

注意：

- 如果要给中国大陆同事长期稳定访问，建议直接做备案。
- 如果你只是内部试用，也可以先用境外地域，但国内访问稳定性通常不如大陆。

官方参考：

- [腾讯云轻量应用服务器](https://cloud.tencent.com/product/lighthouse)
- [腾讯云 PostgreSQL](https://cloud.tencent.com/product/postgres)

## 第 2 步：买服务器

1. 进入腾讯云轻量应用服务器。
2. 选择中国大陆地域，例如上海、北京、广州、成都、南京。
3. 选择入门套餐就够开始试用。
4. 系统选择 Ubuntu 22.04 或 Debian 12。
5. 购买后记录服务器公网 IP。

建议配置：

- 2 核 2G 起步
- 如果人数更多，直接上 2 核 4G

## 第 3 步：开放端口

1. 在腾讯云控制台打开安全组。
2. 放行 `22`、`80`、`443` 端口。
3. 如果你打算先临时调试，也可以保留 `3000` 端口，但正式上线后建议只走 `80/443`。

## 第 4 步：把代码传到服务器

最简单的办法：

1. 在服务器安装 `git`、`docker`、`docker compose` 和 `nginx`。
2. `git clone` 你的 GitHub 仓库。
3. 进入项目目录。
4. 启动项目：

```bash
docker compose -f deploy/tencent/docker-compose.yml up -d --build
```

5. 检查服务：

```bash
curl http://127.0.0.1:3000/healthz
```

这样做的好处：

- 不依赖 Render 这类海外平台
- 国内访问更稳
- 你以后接数据库也方便

## 第 5 步：先确认能打开

1. 用手机浏览器打开 `http://你的服务器公网IP`
2. 确认能看到登录页
3. 用演示账号登录
4. 确认工作、知识、管理、我都能切换

如果这一步失败，先别急着上数据库，先把站点能稳定打开。

## 第 6 步：上 HTTPS

正式给公司人用，一定上 HTTPS。

常见做法：

1. 申请云厂商免费证书。
2. 用 Nginx 反向代理到 `3000` 端口。
3. 把域名解析到服务器 IP。
4. 证书绑定到域名。

建议访问地址长这样：

```text
https://workspace.yourcompany.com
```

项目里已经准备了腾讯云部署材料：

- `deploy/tencent/docker-compose.yml`
- `deploy/tencent/nginx.conf`
- `deploy/tencent/README.md`

你后续照 `deploy/tencent/README.md` 操作即可。

## 第 7 步：再接数据库

当前项目已经准备了 PostgreSQL 表结构：

- `db/schema.sql`
- `db/seed-demo.sql`

正式多人使用时，建议把 JSON 存储切到 PostgreSQL。

步骤：

1. 创建腾讯云 PostgreSQL 实例。
2. 执行 `db/schema.sql`。
3. 导入 `db/seed-demo.sql`。
4. 在服务器里配置 `DATABASE_URL`。
5. 把 `server.js` 的读写从 JSON 文件切到数据库。

提示：

- 现在仓库里已经有表结构，但服务端还没完全切到数据库。
- 所以“先上线网址”可以先跑起来，“正式多人使用”还要做数据库切换。

## 第 8 步：公司内部怎么用

1. 把网址发给员工。
2. 员工打开网址登录。
3. 管理员进“管理”模块维护人员、公告、日程。
4. 员工只看“工作、知识、我”里和自己相关的内容。

## 官网怎么一起做

建议用同一台服务器，但不同域名：

```text
www.yourcompany.com        公司官网
workspace.yourcompany.com  内部管理系统
api.yourcompany.com        未来 App 后端
```

这样比较省钱，也方便后续拆分。

第一阶段：

- 官网可以先做静态页面。
- 内部系统继续用当前项目。
- App 先不打包，先用手机浏览器或添加到主屏幕。

第二阶段：

- 官网图片和视频多了，再接 COS 和 CDN。
- 内部系统多人使用后，再接 PostgreSQL。
- App 需要上架或内部分发时，再用同一个 `api.yourcompany.com`。

## 最低成本建议

如果你现在只想最快上线，我建议：

1. 先买一台腾讯云轻量应用服务器。
2. 先用当前项目跑出一个网址。
3. 先让 3 到 5 个同事试用。
4. 再决定要不要立即切 PostgreSQL。

这样最省钱，也最不容易半路卡住。
